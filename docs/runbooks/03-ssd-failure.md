# F3 — SSD died, pool intact

The most likely serious failure, and the **fastest recovery: everything needed
is already on the pool, so nothing is downloaded**.

| Lost | Survived |
|---|---|
| The OS | `/mnt/storage` — media, photos, documents |
| `/srv/data/configs` (app state) | `/mnt/backups` — the local restic repo, on the pool |
| `/srv/data/db` (databases) | GitHub — all Ansible and compose config |
| `/srv/compose` | The vault, on your laptop |

Expect roughly **2 hours**, most of it the playbook run and Plex's rescan.

---

## Stop and check this first

> **Do not let the Ubuntu installer touch the pool disks.** They are two 3.6 TB
> ext4 disks; the SSD is the 456 GB LVM device. Identify them by serial before
> partitioning:
>
> ```bash
> lsblk -o NAME,SIZE,SERIAL,MODEL
> ls -l /dev/disk/by-id/
> ```
>
> Wiping a pool disk here turns a 2-hour recovery into a 1-day one, and destroys
> the local backup repository you are about to restore from.

> **Mint a fresh Tailscale auth key** at <https://login.tailscale.com/admin/settings/keys>
> before starting. Keys expire after 90 days, so the one in the vault has almost
> certainly lapsed, and `tailscale up` fails with an unhelpful error.
> Update `vault_tailscale_authkey` with the new one.

---

## 1. Install the OS

Ubuntu Server 24.04, same hostname (`mserver`), on the replacement SSD only.
Import your SSH key during install — it saves fighting with password auth later.

## 2. Bootstrap

From your laptop, against the **LAN** address, because the machine is not on the
tailnet yet:

```bash
cd ansible
ansible-playbook playbooks/bootstrap.yml \
  -e bootstrap_ip=192.168.178.35 -e bootstrap_ssh_user=<installer-account>
```

This creates the admin account, installs your keys and passwordless sudo, joins
Tailscale, and asserts the machine came back on the expected address. If it
reports a different tailnet address, remove the dead node in the Tailscale admin
panel and re-run.

## 3. Rebuild everything

```bash
ansible-playbook playbooks/site.yml
```

Re-mounts the pool (the UUIDs are unchanged — same disks), re-clones compose
from GitHub, and recreates every stack, the firewall rules, Traefik, CrowdSec
and the Authentik blueprints. Applications come up **empty** at this point.

## 4. Stop the stacks that own data

```bash
for s in identity paperless productivity kitchen media; do
  docker compose -f /srv/compose/$s/$s.yml down
done
```

## 5. Restore configuration — no download

```bash
export RESTIC_REPOSITORY=/mnt/backups/restic
export RESTIC_PASSWORD_FILE=/etc/restic/password

restic snapshots --tag automated
sudo -E restic restore latest --target / --include /srv/data/configs
```

This is the step that makes F3 fast: the repository is on the surviving pool, so
this runs at disk speed. It brings back the *arr indexers and API keys, quality
profiles, download history, Plex's watch history and playlists, Overseerr's
requests and qBittorrent's seeding state.

## 6. Restore the databases

Follow [02-database-restore](02-database-restore.md) for each, **Authentik
first**. The dumps are in the same snapshot under
`/srv/data/backup-staging/db/`.

## 7. Bring it back up

```bash
ansible-playbook playbooks/site.yml
```

## Gotchas

- **`/srv/compose` needs no restore.** The `docker` role re-clones it from
  GitHub. Do not try to restore it from backup.
- **`.env` files are regenerated by Ansible**, not restored. If one is missing,
  re-run that stack's role tag rather than hunting for it in a snapshot.
- **Check ownership.** Immich, Paperless and Vikunja run as uid 1000 and will
  not read root-owned files:
  ```bash
  sudo find /srv/data/configs/{immich,paperless,vikunja} ! -user 1000 | head
  ```
- **Plex will probably need re-claiming.** Check:
  ```bash
  docker exec plex cat "/config/Library/Application Support/Plex Media Server/Preferences.xml" \
    | tr ' ' '\n' | grep PlexOnlineToken
  ```
  If empty, get a token from <https://plex.tv/claim> — **it expires in 4
  minutes**, so have the next command ready:
  ```bash
  cd /srv/compose/media
  sudo sed -i 's/^PLEX_CLAIM=.*/PLEX_CLAIM=claim-xxxxxxxx/' .env
  docker compose -f media.yml up -d plex
  ```
  Plex serves `Secure connections = Required`, so verify with `https://`, not
  `http://`:
  ```bash
  curl -sk -o /dev/null -w '%{http_code}\n' https://100.78.131.48:32400/identity
  ```

## Verify

```bash
docker ps --filter health=unhealthy          # expect empty
for h in home auth requests tasks recipes fitness photos docs; do
  printf '%-10s %s\n' "$h" \
    "$(curl -s -o /dev/null -w '%{http_code}' https://$h.moritzpalm.com)"
done
```

All 200 or 3xx. Then check the things that only a config restore brings back:
Sonarr still lists your indexers, Plex still shows watch history, qBittorrent is
still seeding.
